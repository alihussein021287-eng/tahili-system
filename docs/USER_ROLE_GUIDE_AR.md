# الدليل التشغيلي العربي لأدوار الموظفين في Tahili

## قبل البدء

هذا دليل استخدام للنظام، لا يقدم نصائح طبية ولا يغير أي حالة. المصدر النهائي هو الكود عند الرأس `d634fae`: `src/lib/perms.ts`، حراس `src/lib/access.ts`، الملاحة في `work-registry.ts`، العمل اليومي في `my-work.ts`، والـServer Actions المحروسة.

الوصول الفعلي ليس مجرد اسم الدور: (1) افتراض الدور، (2) `RolePermission`، (3) `UserPermission`، (4) عضوية المركز أو القسم والفرع، (5) إسناد المراجع/المعالج، (6) حالة السجل أو المرحلة. لذلك ظهور زر أو صفحة لا يمنح الإجراء وحده، والإجراء المرسل بلا المفتاح يرفضه الخادم. افحص دائماً `/my-work` ثم المساحة الجامعة المناسبة؛ هذه القائمة مشتقة ولا تنشئ مهمة أو مرحلة جديدة.

الروابط الجامعة هي: `/patients-care` (المرضى والرعاية)، `/therapy-centers` (المسار العلاجي والمراكز)، `/pharmacy-inventory` (الصيدلية والمخزون)، `/reports-finance` (التقارير والمالية)، `/staff` (الموظفون)، و`/settings` (النظام). المسارات القديمة `/attendance`, `/shifts`, `/tasks` تبقى روابط توافق إلى تبويبات `/staff`.

## مصفوفات سريعة

| الدور | الصفحة الأساسية | التسليم المعتاد |
| --- | --- | --- |
| مدير النظام (ADMIN) | `/settings`, `/staff`, `/my-work` | لا يَحل محل مالك المرحلة إلا بصلاحية موثقة؛ يدير النظام |
| مدير إداري (MANAGER) | `/reports-finance`, `/therapy-centers` | اعتماد/تنفيذ إداري ومتابعة مراكز |

| رئيس المعالجين/معالج | `/therapy-centers` | خطة وإسناد → جلسة → تقييم |
| صيدلي/محاسب | الصيدلية أو المالية | صرف/استلام أو فاتورة/صرفية |

| --- | --- |
| MANAGER مقابل ADMIN | المدير يعتمد ويشرف ضمن مفاتيحه؛ ADMIN وحده افتراضياً يملك المستخدمين والصلاحيات والتدقيق والنسخ والحذف الحصري وكل المفاتيح. |
| RESIDENT مقابل DOCTOR | المقيم يضيف التشخيص وينشئ/يتابع الإحالة؛ الطبيب يملك افتراضياً الوصفة والرقود ومراجعة النتائج وقبول الإحالات. |

| عرض مقابل تنفيذ مقابل اعتماد | المفتاح `*.view` للعرض؛ مفاتيح create/edit/manage للتنفيذ؛ `approve/finalize/pay/execute` لانتقال الاعتماد. |

## بطاقات الأدوار

### مدير النظام (ADMIN)

1. **التعريف والهدف:** مسؤول تشغيل النظام وإدارته. يملك افتراضياً كل مفاتيح `ALL_PERMS`، لكنه يبقى خاضعاً لحالة السجل وحراسة الإجراء.
2. **بداية اليوم:** افتح `/my-work` ثم `/readiness` و`/settings` و`/staff?tab=users` بحسب الحاجة، وراجع التنبيهات والتدقيق لا بيانات المرضى غير اللازمة.
3. **الصفحات:** كل الصفحات بعد الحراس؛ الأهم `/users`, `/permissions`, `/audit`, `/backup`, `/readiness`, `/settings`.
4. **العمل والصلاحيات:** يدير المستخدمين والصلاحيات (`users.*`)، الإعدادات والنسخ (`settings.*`)، التدقيق (`audit.view`) وكل مفاتيح التشغيل. الحذف لا يتم إلا عبر `assertAdminDelete`; تجاوز القفل `therapy.admin.override`.
5. **الحدود والتسليم:** لا يعدل مرحلة سريرية بلا طلب تشغيلي صحيح؛ يرد الحالة إلى مالكها. مثال: «اكتشف مدير النظام أن حساباً اختباريًا لا يرى الصيدلية، فيراجع المفاتيح ولا يصرف وصفة». عند فشل حفظ/حذف أو اعتماد، يراجع سجل التدقيق والرسالة ثم يصعّد للمطور إن كان عطلاً.
6. **تحقق سريع:** الجلسة نشطة؛ الحساب مستهدف صحيح؛ لا حذف بديل؛ لا تغيير صلاحية بلا موافقة؛ راجع AuditLog؛ تحقق من النسخة قبل الاستعادة؛ لا تكشف بيانات حساسة.

### مدير إداري (MANAGER)

1. **التعريف والهدف:** إشراف إداري واعتمادات تشغيلية، لا إدارة حسابات أو صلاحيات كاملة.
2. **بداية اليوم:** `/my-work` ثم `/reports-finance?tab=approvals` و`/therapy-centers?tab=centers`؛ راجع ما ينتظر الاعتماد أو مورد المركز.
3. **الصفحات:** الرعاية والعلاج والصيدلية والمالية والموظفون حسب المفاتيح؛ `/reports-finance`, `/pharmacy-inventory`, `/staff`.
4. **العمل والصلاحيات:** يعتمد شراء (`pharmacy.purchase.approve`) وصرفيات (`expenses.approve`) وتقارير (`reports.approve`)، ينفذ موافقات (`approvals.execute`)، ويدير عضويات/موارد المركز افتراضياً.
5. **الحدود والتسليم:** لا يملك افتراضياً `users.manage`, `users.permissions`, `audit.view`, `settings.*` ولا إنشاء فاتورة/دفعة. يستلم صرفية مقدمة ويسلمها للمحاسب للدفع. مثال: «صرفية اختبارية مكتملة البيانات تُعتمد ثم تعود للمحاسب». يصعّد غياب المفتاح أو الإعداد إلى ADMIN.
6. **تحقق سريع:** الحالة صحيحة؛ المبلغ ظاهر فقط بمفتاحه؛ لا اعتماد شخصي خارج المستوى؛ المركز ضمن النطاق؛ القرار موثق؛ لا حذف.

### استقبال (RECEPTION)

1. **التعريف والهدف:** نقطة دخول المراجع والحضور والمواعيد والطابور.
2. **بداية اليوم:** `/my-work` ثم `/patients-care?tab=visits`, `appointments`, `queue`؛ راجع مواعيد وحضور اليوم.
3. **الصفحات:** المرضى والرعاية، `/search` عند توفر الحارس، و`/patients/[id]` ضمن `patients.view`.
4. **العمل والصلاحيات:** ينشئ/يعدل بيانات المراجع ويطبعها (`patients.create/edit/print`)، يحجز/يعدل موعداً، يسجل حضوراً ويدير الطابور (`visits.manage`, `queue.manage`).
5. **الحدود والتسليم:** لا يملك افتراضياً تشخيصاً/وصفة/إحالة/اعتماد/مبلغ. يستلم المراجع، يسجل الحضور، ثم إلى الطابور والطبيب. مثال: «وصل أحمد الاختباري، بحث الموظف عنه، سجّل الحضور وأدخله الطابور». التكرار أو فشل الحفظ: يوقف العملية ويراجع الرقم مع المدير؛ لا ينشئ سجلاً بديلاً.
6. **تحقق سريع:** بحث قبل إنشاء؛ بيانات صحيحة؛ موعد غير مكرر؛ حضور مسجل؛ طابور صحيح؛ لا تعديل سريري؛ صعّد نقص الصلاحية للمدير/ADMIN.

### مدخل بيانات (DATA_ENTRY)

1. **التعريف والهدف:** إدخال وتحديث بيانات المراجع وتشغيل الحضور والطابور والإحالة الإدارية.
2. **بداية اليوم:** `/my-work` ثم المرضى والمواعيد والإحالات في `/patients-care`.
3. **الصفحات:** `/patients-care?tab=patients|appointments|visits|queue|referrals` عند الصلاحيات، و`/search`.
4. **العمل والصلاحيات:** مثل الاستقبال في المراجع والمواعيد والحضور؛ ويعرض/يطبع/يحدّث إرسال الإحالة ويسجل وصول النتيجة (`referrals.view/print/updateStatus/recordResult`).
5. **الحدود والتسليم:** لا ينشئ إحالة ولا يراجع نتيجتها طبياً ولا يقبلها. يستلم طلباً منشأ، يسجل الإرسال/النتيجة، ثم إلى الطبيب للمراجعة. مثال: «نتيجة إحالة اختبارية وصلت؛ يسجلها دون تفسيرها». صعّد الحالة غير القابلة للانتقال للطبيب أو المدير.
6. **تحقق سريع:** البحث أولاً؛ لا تكرار؛ رقم الإحالة صحيح؛ لا تعديل قرار طبي؛ حالة الإرسال صحيحة؛ سجل النتيجة؛ لا اعتماد.

### طبيب مقيم (RESIDENT)

1. **التعريف والهدف:** محطة سريرية أولية ضمن المفاتيح الفعلية، للتشخيص والإحالة والمتابعة.
2. **بداية اليوم:** `/my-work` ثم `/patients-care?tab=journey` وملف المراجع؛ راجع الحالات المنتظرة.
3. **الصفحات:** ملف المراجع، الرعاية، العلاج والجلسات ضمن الافتراضي، والإحالات.
4. **العمل والصلاحيات:** `clinical.diagnosis`, `referrals.create/updateStatus/recordResult/cancel` إضافة إلى جلسات/جروح/تقارير مفاتيح THERAPIST الموروثة.
5. **الحدود والتسليم:** لا يملك افتراضياً `clinical.prescription`, `clinical.admission`, `referrals.reviewResult/accept`, أو اعتماد التقارير. يستلم من الطابور ويسلم للطبيب أو الإحالة/العلاج. مثال: «بعد فتح حالة اختبارية، يضيف التشخيص ويُنشئ طلب فحص ثم ينتظر النتيجة للطبيب». يصعّد القرار غير المتاح للطبيب.
6. **تحقق سريع:** زيارة صحيحة؛ المراجع الصحيح؛ لا وصفة بلا المفتاح؛ إحالة بحالة صحيحة؛ لا تفسير نتيجة؛ لا اعتماد؛ صعّد للطبيب.

### طبيب (DOCTOR)

1. **التعريف والهدف:** مالك الإجراءات الطبية النظامية ضمن صلاحياته، ومراجعة نتائج الإحالات.
2. **بداية اليوم:** `/my-work` ثم ملف المراجع ومسار الرعاية والإحالات؛ راجع نتائج تنتظر `referrals.reviewResult`.
3. **الصفحات:** `/patients-care`, `/referrals`, `/therapy-centers`, `/reports-finance?tab=patients`، الرقود والأسرة عند المفاتيح.
4. **العمل والصلاحيات:** التشخيص والوصفة والرقود والتقارير وخطة العلاج؛ ينشئ/يقبل/يلغي إحالة ويراجع نتيجتها (`clinical.*`, `referrals.*`)، ويدير الأسرة افتراضياً.
5. **الحدود والتسليم:** لا يعتمد تقريراً رسمياً افتراضياً ولا يدير المستخدمين أو المبالغ/شراء الصيدلية. يستلم من المقيم/الطابور، ثم إلى صيدلية أو مركز أو تقرير. مثال: «يراجع نتيجة اختبارية مسجلة ثم يحدّثها عبر الإجراء المسموح». يصعّد الاعتماد الإداري للمدير.
6. **تحقق سريع:** الملف المقصود؛ لا تعديل خطة مكتملة؛ الإحالة بحالتها؛ الوصفة إلى الصيدلي؛ الرقود مع سرير صحيح؛ التقرير غير معتمد ذاتياً؛ راجع المدير عند الاعتماد.

### رئيس المعالجين (HEAD_THERAPIST)

1. **التعريف والهدف:** يدير خطط العلاج والبرامج والموارد ويشرف على إسناد المعالجين ضمن العضوية.
2. **بداية اليوم:** `/my-work` ثم `/therapy-centers?tab=plans|centers|today` و`/workload`؛ راجع غير المسند ونقص القاعة.
3. **الصفحات:** العلاج والمراكز، ملف المراجع، المهام؛ الموارد والبرامج ضمن المركز.
4. **العمل والصلاحيات:** `therapy.plan.manage/finalize/evaluation.periodic/improvement.update/specialist.assign/schedule.reschedule` و`centers.resources.manage/programs.manage/programs.finalize`.
5. **الحدود والتسليم:** لا يتجاوز عزل المركز أو قفل الخطة، ولا يملك افتراضياً `therapy.admin.override`. يستلم إحالة داخلية ويقبلها، يسند الجلسة للمعالج، ثم يعتمد النهاية المسموحة. مثال: «خطة اختبارية بلا معالج: يحدد المورد والإسناد ثم تظهر للمعالج». صعّد العضوية والإعداد للمدير/ADMIN.
6. **تحقق سريع:** عضوية المركز؛ خطة غير مقفلة؛ معالج مسند؛ قاعة متاحة؛ موعد صحيح؛ تقييم في مرحلته؛ لا وصول لمركز آخر.

### معالج (THERAPIST)

1. **التعريف والهدف:** تنفيذ الجلسات المسندة وتسجيلها ومتابعة التقدم ضمن المركز.
2. **بداية اليوم:** `/my-work` ثم `/therapy-centers?tab=today`; راجع جلسات اليوم المتأخرة أو بلا نتيجة.
3. **الصفحات:** الجلسات والخطط والمراكز وملف المراجع والمهام عند المفاتيح.
4. **العمل والصلاحيات:** `therapy.session.record`, `therapy.improvement.update`, `centers.sessions.record`، وجلسات/مقاييس/جروح/رعاية حسب الافتراضي.
5. **الحدود والتسليم:** لا ينشئ أو ينهي خطة افتراضياً، ولا يدير المورد أو عضوية المركز، ولا يفتح حالة غير مسندة/خارج العضوية. يستلم من رئيس المعالجين ويسلم نتيجة الجلسة أو تنبيه التقييم للرئيس. مثال: «تظهر جلسة اختبارية مسندة؛ يسجل نتيجتها ثم يترك التقييم النهائي للرئيس». صعّد نقص القاعة أو الإسناد للرئيس.
6. **تحقق سريع:** العضوية؛ الإسناد؛ الموعد؛ لا جلسة مكررة؛ النتيجة محفوظة؛ لا إنهاء خطة؛ راجع رئيس المعالجين.

### صيدلي (PHARMACIST)

1. **التعريف والهدف:** صرف الوصفات وإدارة المخزون والدفعات والشراء والاستلام.
2. **بداية اليوم:** `/my-work` ثم `/pharmacy-inventory?tab=dispense|stock|batches`; راجع وصفات الانتظار والنقص والانتهاء.
3. **الصفحات:** الصيدلية والمخزون، صفحة المراجع بالقدر المسموح، وسجل الصيدلية.
4. **العمل والصلاحيات:** `pharmacy.dispense`, `pharmacy.dispense.partial`, `pharmacy.batch`, `pharmacy.print`, `inventory.manage`, `pharmacy.purchase.create`, `pharmacy.purchase.receive`, `pharmacy.purchase.view`.
5. **الحدود والتسليم:** لا يملك افتراضياً اعتماد شراء أو رؤية أسعاره، ولا يكتب وصفة ولا يتجاوز استلام الكمية. يستلم وصفة من الطبيب؛ الصرف يقفل/يحدث المخزون خادمياً. مثال: «وصفة اختبارية صالحة تُصرف جزئياً فقط إن وُجد المفتاح». صعّد النقص/اختلاف الاستلام للمدير.
6. **تحقق سريع:** الوصفة الصحيحة؛ أهلية الصرف؛ دفعة/صلاحية؛ لا تجاوز FEFO؛ جزئي بمفتاح؛ لا سعر/اعتماد بلا مفتاح؛ سجل الاستلام.

### شعبة مالية (ACCOUNTANT)

1. **التعريف والهدف:** إنشاء الفواتير والدفعات والصرفيات وتنفيذ الدفع بعد الاعتماد.
2. **بداية اليوم:** `/my-work` ثم `/reports-finance?tab=finance|wounded`; راجع ما ينتظر الدفع أو التصحيح.
3. **الصفحات:** المالية، صرفيات الجرحى، التقارير، وملف المراجع بالقدر المسموح.
4. **العمل والصلاحيات:** `finance.invoice/payment/receipt/report` و`expenses.create/submit/pay/amounts/print/reports/correct`.
5. **الحدود والتسليم:** لا يعتمد صرفية افتراضياً (`expenses.approve`) ولا يدير المستخدمين ولا يحذف فاتورة. يستلم صرفية معتمدة من المدير ويدفعها، أو يقدم مسودة للمدير. مثال: «ينشئ مسودة صرفية اختبارية، يقدمها، وبعد اعتمادها يسجل الدفع». يصعّد اختلاف المستوى للمدير.
6. **تحقق سريع:** المراجع الصحيح؛ المبلغ ظاهر بمفتاح؛ مسودة قبل تقديم؛ اعتماد موجود قبل دفع؛ سند محفوظ؛ لا حذف؛ راجع المدير عند الرفض/الاعتماد.

### مختبر (LAB)

1. **التعريف والهدف:** محطة المختبر المرتبطة بطلب المراجع؛ توثق النتيجة داخل النظام فقط عندما تمنح الصلاحية الصريحة.
2. **بداية اليوم:** `/my-work` ثم مسار الرعاية أو الإحالات إذا مُنح override؛ افتراضياً لا يملك LAB مفاتيح الإحالة.
3. **الصفحات والصلاحيات:** `STATION_BASE` للعرض/الحضور/المهام والتعاون، و`clinical.report`. لا تفترض زر نتيجة بلا `referrals.recordResult`.
4. **التسليم والحدود:** يستلم الطلب التنظيمي من الطبيب/مدخل البيانات، ويسلم النتيجة المسجلة إلى الطبيب للمراجعة عند منح المفتاح. مثال: «نتيجة مختبرية اختبارية تُسجل فقط عبر المفتاح». غياب المفتاح أو المراجع: صعّد للطبيب/المدير، لا تنشئ إحالة بديلة.
5. **تحقق سريع:** طلب صحيح؛ نطاق الفرع؛ المفتاح موجود؛ لا قرار طبي؛ لا اعتماد؛ التسليم للطبيب.

### أشعة (RADIOLOGY)

1. **التعريف والهدف:** محطة الأشعة المرتبطة بطلب المراجع؛ لا يضيف الدور قراراً طبياً أو انتقال إحالة من تلقاء نفسه.
2. **بداية اليوم:** `/my-work` ثم مسار الرعاية أو الإحالات إذا مُنح override؛ افتراضياً لا يملك RADIOLOGY مفاتيح الإحالة.
3. **الصفحات والصلاحيات:** `STATION_BASE` للعرض/الحضور/المهام والتعاون، و`clinical.report`. تسجيل النتيجة يحتاج تحديداً `referrals.recordResult`.
4. **التسليم والحدود:** يستلم طلب الأشعة من الطبيب/مدخل البيانات، ويسلم النتيجة المسجلة إلى الطبيب للمراجعة. مثال: «نتيجة أشعة اختبارية تضاف بالمسار المصرح ثم تُحال للطبيب». لا ينشئ إحالة ولا يعتمدها أو يراجعها طبياً؛ غياب المفتاح يصعّد للطبيب أو المدير.
5. **تحقق سريع:** الطلب والمراجع صحيحان؛ النطاق صحيح؛ مفتاح النتيجة موجود؛ لا تفسير أو اعتماد؛ لا إحالة بديلة؛ التسليم للطبيب.

### تضميد (DRESSING)

1. **التعريف والهدف:** محطة التداوي والتضميد في النظام، لا قرار تشخيصي مستقل.
2. **بداية اليوم:** `/my-work` ثم ملف المراجع/مسار الرعاية؛ راجع الحالات المسندة.
3. **الصفحات والصلاحيات:** `STATION_BASE` و`clinical.wound`, `clinical.care`.
4. **التسليم والحدود:** يسجل التقييم/الرعاية ضمن المفتاح، ثم يسلم المتابعة للطبيب أو محطة العلاج. لا وصفة أو تشخيص أو اعتماد افتراضي. مثال: «يسجل رعاية اختبارية في الملف ثم يخطر الطبيب بالمراجعة المطلوبة». فشل الحفظ أو مرحلة غير صحيحة: الطبيب ثم ADMIN عند عطل صلاحية.
5. **تحقق سريع:** المراجع الصحيح؛ الإجراء ضمن المفتاح؛ لا تعديل تشخيص؛ لا حذف؛ حالة المسار لا تتغير يدوياً؛ تسليم موثق.

### أطراف صناعية (PROSTHETICS)

1. **التعريف والهدف:** محطة تسليم وصيانة الأجهزة/الأطراف في النظام.
2. **بداية اليوم:** `/my-work` ثم `/devices` ومسار الرعاية؛ راجع التسليم والصيانة المفتوحة.
3. **الصفحات والصلاحيات:** `STATION_BASE` و`devices.view/create/maintain`.
4. **التسليم والحدود:** يسجل التسليم أو الصيانة، ثم يسلم النتيجة للملف/الطبيب. لا يحذف جهازاً (`devices.delete` ADMIN) ولا يدير المخزون أو الصرفية افتراضياً. مثال: «يسجل تسليم جهاز اختباري ويضيف صيانة لاحقة من الإجراء المسموح». صعّد الاستبدال غير المتاح للمدير.
5. **تحقق سريع:** الجهاز والمراجع صحيحان؛ لا حذف؛ الصيانة موثقة؛ لا تعديل مالي؛ سجل التسليم؛ راجع المدير عند تعارض.

### مشاهدة فقط (VIEWER)

1. **التعريف والهدف:** متابعة تشغيلية محدودة. الاسم لا يكفي لتحديد المنع: افتراضياً يملك بعض التنفيذ منخفض الخطورة مثل إنشاء/إكمال مهمة والتعاون.
2. **بداية اليوم:** `/my-work`, `/workspaces`, ثم المرضى أو التقارير التي يظهرها المفتاح.
3. **الصفحات والصلاحيات:** عرض المراجع/السريري والمواعيد والطابور والزيارات والتقارير والمهام والمسار والملفات/المحادثة الأساسية.
4. **الحدود والتسليم:** لا يملك افتراضياً `patients.edit/create`, `clinical.*` التنفيذي، إحالات، مالية، صيدلية، اعتماد أو إعدادات. يستلم متابعة ويحولها بمهمة/تعاون لمالكها. مثال: «يرى حالة اختبارية وينشئ مهمة متابعة، ولا يغير السجل». نقص الوصول يصعّد للمدير/ADMIN.
5. **تحقق سريع:** عرض فقط للبيانات؛ لا محاولة تعديل؛ مهمة للمسؤول الصحيح؛ رابط التنبيه مسموح؛ لا مبلغ/اعتماد؛ لا تصدير بلا مفتاح.

## الدورات المشتركة

راجع [خريطة التسليم](ROLE_WORKFLOW_HANDOFFS_AR.md) لكل الدورات المثبتة: التسجيل والحضور، الزيارة والطابور، المقيم والاختصاص، الإحالات، الوصفات والصيدلية، الرقود، العلاج الطبيعي، التأهيل النفسي والوظيفي ومركز النقاء، التقارير، المالية والاعتمادات، الموظفين، التعاون، التنبيهات، وإدارة النظام.

## متى تطلب المساعدة؟

- **رئيس المعالجين:** إسناد أو عضوية مركز أو قاعة أو خطة/جلسة.
- **الطبيب:** تشخيص أو وصفة أو قرار نتيجة/إحالة أو حالة سريرية ليست من محطة الموظف.
- **المدير:** اعتماد أو رفض أو مورد/شراء أو صرفية أو حالة تشغيلية متعددة الأقسام.
- **مدير النظام:** مستخدم أو صلاحية أو إعداد أو تدقيق أو نسخ أو حذف حصري أو عطل حراسة بعد توثيق الرسالة.

لا تتجاوز صلاحية غائبة ولا تغير حالة يدوياً. عند عدم ظهور المراجع، المركز أو القاعة: تحقق من البحث/الفرع/العضوية/الحالة، وسجل المشكلة دون بيانات حساسة ثم صعّد للمالك أعلاه.
