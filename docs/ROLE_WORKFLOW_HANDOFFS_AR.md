# خريطة تسليم العمل بين الأدوار — Tahili

> هذه خريطة تشغيلية وليست وصفاً طبياً. تنتقل الحالة فقط عبر Actions وخدمات النظام المحروسة؛ لا يجوز استخدام الدليل لتجاوز حالة أو صلاحية. نقطة الإغلاق هي ما يثبته الكود أو الوثائق المرجعية، لا قرار موظف فردي.

| الدورة | المسار المثبت |
| --- | --- |
| تسجيل المراجع والحضور | مراجع جديد → DATA_ENTRY بـ`patients.create` → الاستقبال → `visits.manage` لتسجيل الحضور → `queue.manage` لإدخاله للطابور → زيارة/محطة تالية؛ مدخل البيانات لا يسجل الحضور أو يدير الطابور |
| الزيارة والطابور | حضور مراجع مسجل من RECEPTION → RECEPTION أو ADMIN بـ`queue.manage` → RESIDENT/DOCTOR أو محطة العمل → الحالة تسجل في `QueueEntry` |
| تسليم المراجع | خدمة `handoff-service.ts` الداخلية: سياق جلسة وصلاحيات موثق من الخادم وحراسة الوصول للملف عند الاستدعاء → `handoff.send` للإرسال والإرجاع، و`handoff.receive` مع أهلية المستلم للاستلام → عضوية مركز فعالة بالدور المحدد أو استقبال/إدخال بيانات في فرع المراجع أو مستخدم معين فعال. الاستلام ذري ويضيف انتظاراً للمركز عند غيابه في يوم بغداد؛ الإرجاع يحتاج سبباً ويعيد التسليم للمرسل؛ إرسال المستلم يغلق تسليمه السابق. لا يغير `CareStage` أو مسار المراجع الطبي. |
| توجيه السكرتارية | RECEPTION أو DATA_ENTRY في الفرع (`Branch` = الموقع) → `handoff.send` إلى SECRETARY/سكرتارية المركز → `handoff.receive` من السكرتارية → RESIDENT → THERAPIST في المركز (`Center` = القسم)، مع تحقق عضوية المركز الفعالة لكل دور. السكرتارية تتابع الملف والمواعيد وطباعة/تحديث إرسال الإحالة فقط؛ لا تنشئ ملفاً أو إحالة ولا تسجل نتيجة أو حضوراً أو طابوراً. يرى كل مستخدم تسليماته المصرح بها فقط؛ التوجيه لا يغير المرحلة الطبية. |
| المقيم والعلامات والجروح | طابور/ملف → RESIDENT أو مخول → `clinical.diagnosis`، وعند منحه المفاتيح المناسبة `clinical.wound/metrics` → DOCTOR/إحالة/علاج → السجل المحفوظ، وليس نصيحة طبية |
| الاختصاص والاستشارية | إحالة أو ملف → DOCTOR → تشخيص/وصفة/رقود/مراجعة نتيجة حسب المفاتيح → صيدلية/مختبر/أشعة/مركز/تقرير → Action محروس وحالة السجل |
| الفحوص والإحالات | DOCTOR/RESIDENT → `referrals.create` → DATA_ENTRY/MANAGER للطباعة أو تحديث الإرسال حسب المفاتيح → LAB/RADIOLOGY أو الجهة الداخلية → `recordResult` ثم DOCTOR `reviewResult` → `REVIEWED` خارجيًا أو `ACCEPTED` داخليًا؛ الإلغاء `CANCELLED` نهائي |
| الوصفات | DOCTOR أو مخول `clinical.prescription` → وصفة → PHARMACIST `pharmacy.dispense` (وجزئي فقط مع `pharmacy.dispense.partial`) → مخزون/دفعة → حالة الصرف الذرية |
| الصيدلية والمخزون والشراء | حاجة مخزون → PHARMACIST `pharmacy.purchase.create` → MANAGER/ADMIN `pharmacy.purchase.approve` → PHARMACIST `pharmacy.purchase.receive` → دفعات/مخزون → سجل الاستلام؛ الأسعار لا تعرض بلا `pharmacy.purchase.prices` |
| الرقود والفندقة وأدوية الراقدين | DOCTOR أو مخول `clinical.admission` → `beds.assign` → سرير → مخول `meds.manage` يسجل الجرعات → خروج/تحديث رقود وفق Action → الإشغال الصحيح |
| العلاج الطبيعي | إحالة/خطة → HEAD_THERAPIST `therapy.plan.manage` والجدولة/الإسناد → THERAPIST المسند وعضو المركز `therapy.session.record` → رئيس المعالجين/مخول `therapy.plan.finalize` → خطة نهائية وفق الحالة |
| التأهيل النفسي | إحالة داخلية → HEAD_THERAPIST/عضو مخول `centers.programs.manage` → جلسة/تقييم مركز → مخول نهائي `centers.programs.finalize` → برنامج منتهٍ؛ الملاحظة الحساسة تتطلب `centers.psych.sensitive` |
| العلاج الوظيفي | برنامج مركز → رئيس/مخول يدير الموارد والقاعة → معالج عضو يسجل الجلسة → رئيس/مخول ينهي البرنامج → لا يعبر المركز بلا عضوية |
| مركز النقاء | إحالة/برنامج → عضو المركز المخول → الموارد والجلسات في مساحة المركز → تقييم/نهاية البرنامج → النطاق محفوظ بـCenterMembership |
| التقارير والإجراءات الرسمية | ملف/طلب → DOCTOR أو مخول `clinical.report`/`officialdocs.manage` → تقرير أو مستند → MANAGER/ADMIN عند `reports.approve` → `reports.print` أو صفحة الطباعة → التقرير/المستند المعتمد |
| الصرفيات والاعتمادات | ACCOUNTANT `expenses.create` → `expenses.submit` → MANAGER/ADMIN `expenses.approve` → ACCOUNTANT `expenses.pay` → سند `expenses.print` → مدفوع/مصحح وفق الحالة؛ المبلغ يحتاج `expenses.amounts` |
| المهام والحضور والشفتات | منشئ مخول `tasks.create` أو `shifts.manage` → الموظف `tasks.complete` أو يسجل الحضور عند `attendance.manage` → MANAGER/ADMIN `shifts.approve` → المهمة/الطلب بحالته المسجلة |
| التعاون والدردشة والملفات | مستخدم مخول → محادثة/رسالة/رفع (`chat.*`, `files.*`) → مشاركة ضمن القسم/المركز وبعد فحص الملف SAFE → المستلم المخول → إغلاق المشاركة أو إدارة المشرف؛ لا فتح قبل الفحص |
| التنبيهات والمتابعة | Action وظيفي ينشئ Notification → المستخدم المستهدف → `/notifications` → الرابط يمر `canOpenNotification` → فتح الرابط أو بقاؤه مخفياً |
| المستخدمون والإعدادات والنسخ والجاهزية | ADMIN → `users.manage/users.permissions/settings.*` → ضبط/تدقيق/نسخ → Admin أو إجراء إدارة آخر → أثر AuditLog وإتمام العملية؛ لا تسليم تشغيلي لدور عادي |
| تعيين موظف لمركز | ADMIN → ملف المستخدم «مراكز العمل» → إضافة/تعديل/نقل أو إنهاء عضوية `CenterMembership` → فريق المركز والتحويلات المستقبلية؛ للأدوار ذات المركز الواحد ينهي النقل الارتباط الفعّال السابق مع بقاء السجل، وللمعالج ومشغّل الجهاز يسمح النظام بأكثر من مركز. لا يُنشأ حساب جديد ولا يتغير تاريخ المراجع أو التحويلات السابقة. |

## ضوابط إرسال التسليم

لا يرسل الموظف تسليماً جديداً إذا بقي تسليم `SENT` أو `ACCEPTED` آخر للمراجع، باستثناء تسليمه الذي استلمه بنفسه ويُغلق `DONE`. حامل `handoff.manage` أو الدور الفعلي `MANAGER`/`ADMIN` يستطيع الإرسال مع إلغاء التسليمات المفتوحة الأخرى `CANCELLED` وتدقيق معرّفاتها في المعاملة نفسها. يبقى `handoff.send` والوصول لملف المراجع مطلوبين.

يُشتق مركز الإرسال من مركز التسليم المستلم، وإلا من عضوية المرسل الفعالة الوحيدة، وإلا `null`؛ لا يختاره العميل. أهلية المستلمين وقائمة الأهداف تتطلب عضوية سارية بتاريخ البداية والنهاية وحساباً فعالاً ومفتاحي `handoff.receive` و`handoff.send` بعد تعديلات الدور والمستخدم. الاستقبال وإدخال البيانات يتطلبان فرعاً للمراجع. يسجّل الإرسال الجهات والمراكز ومعرّف التسليم المغلق في التدقيق وينشئ لكل مستلم إشعاراً إلى `/my-work`؛ فشل التدقيق أو الإشعار يلغي المعاملة كلها.

يُنهي المستلم الذي قبل التسليم حالة `ACCEPTED` إلى `DONE`؛ ويمكن للمرسل أو حامل `handoff.manage` أو المدير/مدير النظام إلغاء `SENT` فقط. تعيد سكرتارية المركز ذات العضوية الفعالة، أو المدير، توجيه `SENT` داخل المركز نفسه: يُلغى التسليم السابق ويُنشأ تسليم جديد مرتبط به مع الملاحظة نفسها وإشعار المستلمين المؤهلين. أرشفة ملف المراجع أو خروج رقوده تغلق تسليماته المفتوحة إلى `DONE` مع تدقيق كل انتقال.

في `/my-work` تُعرض التحويلات الواردة بحسب المركز المحدد في صفحات من 20، وتسبق `SENT` حالات `ACCEPTED` مع ترتيب التأخير الأحمر ثم الأصفر ثم الأخضر والأقدم أولاً داخل اللون. يعرض قسم «أرسلتها اليوم» تحويلات المرسل في يوم بغداد وحالة كل منها واسم من استلمها؛ يظهر الإلغاء فقط ما دامت `SENT`. تحديث الصفحة التلقائي كل دقيقة أثناء ظهورها لا يغير حالة التحويلة.

## قاعدة التصعيد

حدود متابعة التسليم حسب دور المستلم: SECRETARY وRECEPTION وDATA_ENTRY عشرون دقيقة؛ RESIDENT ثلاثون؛ DOCTOR خمس وأربعون؛ HEAD_THERAPIST 240 دقيقة؛ THERAPIST ثلاثة أيام. إذا اختلف مركز الإرسال عن مركز الاستلام فالحد 24 ساعة. مؤشرات التأخير تنبه المستخدم ولا تستلم المهمة أو تنقلها تلقائياً.

فشل الحفظ أو غياب المفتاح أو عدم ظهور مركز/قاعة ليس سبباً لتبديل الدور أو طلب تجاوز. يوثق الموظف رقم السجل غير الحساس ورسالة الخطأ، ثم يصعّد لمالك المرحلة: رئيس المعالجين للمركز والجلسة، الطبيب للملف/الإحالة، المدير للاعتماد التشغيلي، وADMIN للمستخدمين والصلاحيات والإعدادات والنسخ والحذف الحصري.
